## 2. 一期端到端样本

至少准备两个企业或等价隔离样本，验证一个企业无法访问另一个企业的数据；业务闭环至少使用一个真实内部项目和一个真实上游模型。

1. 平台管理员创建企业 A，并指定企业管理员。
2. 在企业 A 下创建项目 P，开通模型 M，分配额度 Q。
3. 为 P 创建两个 API Key，分别通过在线体验和 API 发起调用。
4. 核对调用记录的企业、项目、模型、输入/输出 Token、内部成本、状态及余额变化。
5. 使用无权限账号或企业 B 的账号访问 P，验证 API 拒绝且不泄漏对象是否存在。
6. 调用未开通模型，验证拒绝及错误记录。
7. 并发消耗至额度边界，验证不会超发或重复结算。
8. 模拟上游拒绝、超时和部分流式输出，按 Q-02 结算并记录。
9. 停用一个项目 Key，验证停用 Key 被拒绝，另一个 Key 仍按授权运行。
10. 触发额度不足和渠道故障，核对提示、告警记录及恢复状态。

## 3. 证据规则

- 每次验收记录环境、应用 commit/tag、数据库迁移版本、配置版本、执行人和时间。
- API 验收保存脱敏请求/响应、断言和测试输出；UI 验收保存关键截图或录屏。
- 额度与成本验收保存输入数据、计算口径、期望值和实际值，不能只保存页面截图。
- 生产凭证、Cookie、个人信息和未经脱敏的请求内容不得进入 Git。
- 失败项必须关联缺陷或变更记录；修复后保留复测证据，不覆盖历史结论。
