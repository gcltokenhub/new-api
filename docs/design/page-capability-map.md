## 2. 页面通用状态

每个数据页面至少设计并实现：加载中、无数据、正常、有权限但不可操作、未授权、额度不足、服务异常及重试。删除/停用、密钥首次展示、表单重复提交和会话失效需要单独交互规则。

所有统计明确单位、统计周期、时区、更新时间及数据延迟。所有成本视图区分“用量”“额度”“余额”“内部成本”，不混用 Token 数与货币金额。

## 3. 能力复用核查

| 能力 | 预期策略 | 源码确认后记录 |
|---|---|---|
| 用户认证与用户管理 | 复用并限制一期角色 | 入口、会话、权限模型 |
| 渠道、上游 key 池、模型 | 复用 | 配置实体、健康状态、故障切换能力 |
| 用户/API 令牌 | 复用核心，增加项目归属 | 密钥显示、停用、范围、兼容性 |
| 请求转发与限流 | 复用 | 支持协议、流式、重试、错误映射 |
| 额度扣减与日志 | 复用核心计量，扩展项目与内部成本归属 | 预扣/结算、并发、失败、日志字段 |
| 企业、项目、开通关系 | Token 工厂业务层 | 数据模型、唯一性、生命周期、隔离 |
| 接入申请与基础告警 | 评估新增薄功能 | 存储、权限、通知策略 |

接口清单不得从页面文案反推。每个页面开发前登记真实端点、方法、权限、请求/响应、错误码和来源代码位置。

## 4. 视觉实现原则

- 门户首页以 Figma `31:2` 为验收依据；语义样式以 `14:2` 为基础。
- 动态模型、价格、节点指标和服务状态必须来自可维护数据源，或者明确标为静态介绍。
- 首页桌面稿不能自动定义移动端布局；移动端范围经 Q-04 确认后补充断点和验收图。
- 开发时应使用 Figma 的设计上下文、变量和资源，不依据压缩截图猜测精确颜色或间距。
