# Token工厂前端视觉与交互规范

- 状态：已确认，自 2026-09-16 起作为前端新增与修改的默认规范。
- 范围：门户、认证页、控制台、管理后台及弹窗、表单、空态。
- 关联：TF-103 / AT-103；[需求基线](../requirements/v1-platform-foundation-prd.md)、[页面映射](v1-platform-foundation-page-map.md)、[工程规范](../../web/AGENTS.md)。
- 依据：[已核验的 Figma 来源](../requirements/sources.md)，Foundations `14:2`、门户首页 `31:2`，以及已保存的设计图和现有实现。未重新提取 Figma 变量；本文不表示全站已完成视觉改造。

## 1. 风格与适用原则

延续企业级 AI 云服务门户的专业、清爽、可信风格：品牌蓝、青绿辅助、清晰字阶、规整网格、充足留白、轻量卡片和少量重点渐变。

新增页面和区块必须遵循本规范；已有页面在本次修改范围内逐步统一，不借机重写无关业务。具体页面已有确认设计时，按该设计确定布局细节并保留共同品牌语言；偏离规范需在变更说明中记录原因。

| 场景 | 应用方式 |
| --- | --- |
| 门户与产品介绍 | 宽屏居中、大标题、大区块留白；首屏价值说明与示意图并列；浅色主体配局部深色区块；底部突出接入操作 |
| 登录与注册 | 简洁表单和清晰品牌；装饰轻量，不挤压输入区域 |
| 控制台与管理页 | 共享颜色、字阶、圆角和卡片语言；工具栏、表格和表单保持紧凑，优先保证扫描效率与操作可达 |
| 弹窗与抽屉 | 使用已有封装，明确标题、内容、主次操作，保持字段与间距一致 |

控制台不照搬门户的大首屏、轨道插画及营销留白。门户深色算力区是内容分区，不代表全站暗色主题。

## 2. 色彩与主题

下表来自现有 [portal.css](../../web/src/styles/portal.css)，是实施参考色值，不是已精确提取的 Figma 全站 token。

| 用途 | 参考色值 | 使用方式 |
| --- | --- | --- |
| 品牌蓝 | #1764F5 | 主要按钮、选中态、链接、标题关键词与焦点 |
| 青绿辅助 | #14B8A6 | 状态点、少量装饰；文字使用更深色以保持可读性 |
| 主背景 / 次级背景 | #FFFFFF / #F4F7FB | 页面与区块层次 |
| 主文字 / 辅助文字 | #172033 / #62718A | 标题正文与说明 |
| 边框 / 浅蓝底 | #DCE5F2 / #EFF5FF | 分隔与次级操作背景 |
| 门户深色区块 | #101827 | 算力等重点内容区，搭配高对比文字 |

- 业务组件使用语义化主题变量和工具类，如 `bg-primary`、`text-foreground`、`border-border`，不逐组件复制色值。
- 全站主题入口为 [theme.css](../../web/src/styles/theme.css) 和 [theme-presets.css](../../web/src/styles/theme-presets.css)。门户样式限定在 `.token-portal` 内；全站品牌推广通过主题层完成。
- 成功、警告、错误使用语义色；危险操作使用 destructive 语义，不把所有状态改成品牌蓝。状态同时提供文字或图标说明。
- 保留已有暗色模式和用户主题设置；共享组件同时验证明暗主题，不能用浅色硬编码破坏暗色页面。

## 3. 字体与信息层级

- 使用现代无衬线字体。门户参考 Noto Sans、Microsoft YaHei、sans-serif；字体声明不等于已加载字体文件。全站字体通过主题统一配置，不逐页面加载字体包。
- 以下为项目实施约定：门户主标题 34–52px、区块标题 25–34px；控制台页面标题 24–28px；卡片标题 16–18px；正文 14–16px；辅助信息 12–14px。按屏宽调整，营销标题尺寸不用于表格和表单。
- 标题字重 600–700、正文 400–500；标题行高约 1.3–1.4、正文约 1.5–1.8。
- 蓝色强调少量核心关键词。小型英文标签可适度增加字距，中文正文不使用夸张字距。
- 保持真实的标题层级和可选择、可复制正文；面向用户的文案支持 i18n。

## 4. 布局、间距和卡片

- 新增间距优先采用 4px 步进：4、8、12、16、24、32、48、64；同级内容统一间距。
- 门户参考最大内容宽度约 1264px，桌面区块上下留白约 80–100px；移动端减少留白、降低列数。控制台按任务和现有布局分配宽度，不强制门户宽度。
- 卡片间距一般 16–24px，内边距一般 20–24px；数据密集区域可采用 12–16px，保持一致。
- 圆角优先 8 / 12 / 16px 三级，对应控件、普通卡片、大容器。品牌示意图可使用更大圆角，不推广到全部控件。
- 卡片采用细边框或轻阴影；避免粗边框、重阴影和光晕重复叠加。
- 渐变和光晕集中于门户首屏、重点服务卡和接入横幅；表格、表单和普通业务卡采用稳定的纯色阅读背景。
- 门户首屏内容容器 `.portal-hero-grid` 不叠加背景渐变，透出 `.portal-hero` 的区块背景（2026-09-18 用户调整）。

## 5. 组件与操作

- 修改 UI 前执行 [前端工程规范](../../web/AGENTS.md) 中的检索与复用流程，读取项目 shadcn-ui 技能。优先复用 dialog、confirm-dialog、copy-button、data-table 等业务封装，再组合 `src/components/ui/`。
- 品牌色实心按钮用于主要操作，描边或浅底按钮用于次要操作，文字链接用于轻量导航。同一操作组主次清晰，尺寸优先沿用已有组件规格；门户主要操作目标高度约 44px。
- 表格筛选、分页、复制和确认沿用已有交互；数值对齐，长文案明确换行或截断，重要内容可查看完整值。
- 覆盖 loading、empty、error、disabled、hover、focus-visible、selected 状态；失败不能显示成零数据。
- 使用已有图标系统，品牌 Logo 使用专用资产。装饰不承载正文或操作，禁止整页截图、区块截图和透明热点替代真实组件。
- 站点名称优先原样使用后台“系统名称”设置，“Token工厂”仅为空配置默认值，不得重新引入硬编码的 New-API 品牌展示及仓库、文档、社区、反馈、上游更新入口；源码版权、许可证和内部协议标识按原义保留。

## 6. 响应式与可访问性

- 验证窄屏、平板和桌面；页面不横向溢出，宽表格在自身容器内滚动，导航与操作不能被裁掉。
- 操作支持键盘，焦点清晰；按钮、链接语义正确，表单有可访问名称，装饰图标对辅助技术隐藏。
- 检查正文、浅底按钮与状态标签的对比度，不以降低整体透明度牺牲可读性。
- 动效用于状态反馈，优先短暂颜色、透明度或轻微位移变化；尊重 reduced-motion 偏好，不新增持续闪烁和干扰阅读的背景动画。

## 7. Figma 落地与验收

有具体 Figma 节点时读取结构与截图，再映射到项目组件、主题和已有路由。工具不可用时明确使用已有设计图和记录，不声称精确还原。设计稿价格、SLA、容量和节点状态不直接作为真实数据或产品承诺。

每次 UI 交付检查：

- 品牌、配色、字阶、间距、圆角及同级组件是否一致。
- 信息密度是否符合门户或工作台场景，主操作是否清晰。
- 明暗主题、窄屏、长文案、键盘焦点及加载/空/错误状态是否可用。
- 是否复用了业务组件，是否存在截图页面、重复封装或无效入口。
- 执行受影响测试、类型检查与文件 lint；视觉变更补充浏览器检查，如实记录范围，不以自动化通过替代视觉验收。

本次仅建立规范；现有页面的符合程度仍需逐页验收，不涉及接口变更。
