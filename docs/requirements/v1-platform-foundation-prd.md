## 1. 目标与成功标准

在 2026 年 9 月底前交付可运行的 Token 平台基础版。平台以 `QuantumNous/new-api` 为二次开发基座，保留原生的渠道、Token、转发、用量、日志、限流和用户能力；门户完成 Token 工厂的 P0 品牌与关键页面改造，并具备从开发到生产的可验证部署方案。

成功不以页面静态展示为准：已授权用户能够管理 Token，并通过原生 API 网关链路完成一次可追溯的请求；控制台显示定义清晰的基础运行数据；部署配置可在相应环境启动或经基础设施验收。

## 2. 产品与架构边界

| 边界 | 当前决定 |
| --- | --- |
| 上游基座 | `QuantumNous/new-api`（Go 后端、React 前端、AGPLv3）。导入时记录精确 tag/commit、许可证义务与本地改动。 |
| 平台核心 | 复用上游渠道管理、Token/API Key、额度、请求转发、日志、速率限制和用户管理。 |
| Token 工厂定制 | 品牌、门户首页、控制台总览、Token 管理及少量支撑这些页面的接口扩展。 |
| 推理资源 | 物理 GPU 节点可承载 vLLM/TGI 等推理服务；华为云承载面向外部的 New-API 集群与托管数据服务。具体拓扑须以基础设施验收为准。 |
| CC-Switch | 用于 Claude Code、Codex、Gemini CLI 等本地工具的路由控制、格式转换、熔断和切换。它不是当前生产网关的替代品，生产计量/计费归 Token 平台。 |

## 6. 关键技术约束

- 集群实例共享 SQL 数据源；使用共享 Redis 时，`SESSION_SECRET` 与 `CRYPTO_SECRET` 必须一致。
- 同步频率、会话、缓存、数据库迁移和密钥轮换必须配置化并记录版本；不得把真实密钥提交到 Git。
- 任何前端重构先确认上游目录与构建入口，再决定最小侵入的改造方式。
- 设计实现以 [平台基础版页面映射](../design/v1-platform-foundation-page-map.md) 和 Figma 为准；未提供设计稿的控制台页面先完成信息架构与验收定义。

## 7. 验收与待确认项

验收标准见 [平台基础版验收](../testing/v1-platform-foundation-acceptance.md)。当前以下信息未确认，不应由实现自行假设：

1. AGPLv3 对本项目发布方式的合规结论，以及采用直接 fork 或保留本仓库治理历史后导入源码的方式。
2. 首批模型/渠道、可使用的测试凭据和对外开放范围。
3. 总览指标的口径、币种、时区、时间范围与刷新频率。
4. Token 分组、批量操作、额度与有效期的业务规则及角色权限。
5. 物理节点和华为云资源的可用性、网络连通、安全边界、备份/恢复目标和运维责任人。

## 前端品牌文案补充（2026-09-16）

所有内置前端页面的 New-API / New API / NewAPI 品牌展示统一为“Token工厂”，覆盖公共页、控制台、管理设置、渠道名称、多语言文案及页面标题。上游接口、协议标识、链接地址及源码版权信息保持原义；不修改用户自定义内容或历史业务数据。

### 品牌入口补充（2026-09-16）

在品牌文案统一基础上，移除内置前端的 New-API 仓库、文档、社区、反馈和上游版本更新入口。已配置的导航文档、页脚链接、插件网站与更新日志来源链接若指向旧品牌，也不显示。源码版权及许可证说明、插件安装数据源和内部接口保持不变；不改写管理员自定义 HTML / Markdown 内容。

### 前端视觉规范（2026-09-16）

TF-103 的品牌定制和页面改造遵循 [前端视觉与交互规范](../design/frontend-visual-guidelines.md)。后续前端新增与修改共享品牌语言，按门户、认证、控制台及管理场景适配信息密度。本次建立规范，不表示全站改造完成，不新增后端能力。

### 系统名称配置优先（2026-09-17）

TF-103 / AT-103：按用户最新要求，站点标题、导航和门户页脚原样采用后台系统名称，包括含 New API 的自定义名称；取消前端旧品牌字符串替换。Token工厂仅作空配置默认名称。此规则覆盖此前强制统一站点名称的要求，旧品牌外链移除规则继续有效，接口不变。
